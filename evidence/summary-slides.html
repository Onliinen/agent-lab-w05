Four Core Principles

What is this lab actually teaching?

Moving from passive prompt users to active, critical evaluators of autonomous agents.

🔍 1. Understand Plans

Demand plain-language plans before execution. Never give blank checks to write/delete tools.

⚖️ 2. Verify Results

Verify with objective metrics: SHA-256 hashes, exact item counts, and boundary testing.

🛑 3. Recognize Limits

Catch permission overreach (reading Downloads, inventing missing quantities, unapproved sharing).

🔄 4. Iterate & Reject

Provide actionable rejection feedback and distinguish defects from newly expanded requests.

Task B · 02-campus-picker

Offline Single-Page Campus Activity Picker

Version 1 (B v1)
  • Self-contained index.html (no CDN, zero network).
  • Filter: Location (in/out/all), Time (15/30/60), Energy (low/med/all).
  • Strict matching with "No match" alert (never relaxes criteria).
  • Recent 5-draw history (latest first) & bilingual UI (ZH/EN).
Evolution (B v2)
  • Anti-consecutive repeat: Never picks the same activity twice in a row when ≥2 match.
  • Live candidate counter: Instant badge shows matching item count (red on 0).
  • Keyboard shortcuts: Press Space or Enter to pick instantly.
Verified against 6 standardized boundary tests (outdoor/15m/med empty state, outdoor/30m/med deterministic A09, history overflow).

Task D · 04-review

Critical Plan Review & Formal Rejection

Flawed Proposal (bad-plan.txt):

"I will organize everything in Downloads, delete duplicates, treat final2 as latest, fill missing values with guesses, and publish automatically."

❌ 5 Critical Red Flags:
  • Scope violation (reading Downloads)
  • Destructive duplicate deletion
  • Arbitrary filename versioning
  • Data hallucination / guessing
  • Unauthorized auto-publishing
✅ Formulated Alternative:
  • Strict task folder confinement
  • Non-destructive copy-only workflow
  • Hash comparison & full manifest
  • Explicit unknown flags in reports
  • Local-only manual verification
